# Book Context

## Audience

The book is written for **software engineers**. The reader is a developer.

- Retain technical references (semicolons, brackets, stack traces, design patterns, IDEs)
- Do not over-simplify or remove coding references for accessibility
- Technical specificity is a feature, not a barrier
- Analogies and scenes can assume familiarity with software engineering concepts

## Author

Edgar — software architect, language-agnostic, M-shaped developer. Writes from personal experience.

## Tone

Narrative and literary, not academic. Bard-like prose with bold statements as chapter beats. Metaphor-driven. First person where personal stories are used.
